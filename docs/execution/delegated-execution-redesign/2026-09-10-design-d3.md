# d3 — 기존 SDD 교체와 세션 운영 범위

작성일: 2026-09-10. 사용자 방향 변경을 반영한 설계 revision.
d1/d2와 과거 승인·실험 기록은 보존한다. 충돌하는 범위에서는 아래 결정이 우선한다.
상세 구현 전체를 승인한 기록은 아니다.

## 변경 근거

- 사용자: “기존 SDD 공존은 필요 없다고 생각해 없어도 가능할거라고 보거든”.
  d1 D1의 legacy 공존은 에이전트가 추천했던 선택이며, 이제 새 workflow로 교체한다.
- 앞선 사용자: “후자는 말이 안되는것 같아, 애초에 판단을 내릴 주체가 사라졌는데, 스크립트만 돌아서 의미가 없잖아”.
  세션 종료 후 무인 지속 실행은 에이전트가 넓힌 범위였다. 이를 지원 목표에서 제외하고
  작업 세션 안의 AI 판단과 script 실행 책임 분리, 중단 후 새 세션 재개에 집중한다.

## 현재 설계 결정

1. 제품 실행 경로는 새 위임 workflow 하나로 구성한다. 기존 Spec→Design→Plan 강제 전이,
   단계별 승인 경로, 구형 실행 orchestrator를 별도 사용 모드로 유지하지 않는다.
2. 구형 CLI/state schema와의 runtime 호환 계층이나 자동 migration은 필수 범위가 아니다.
   구형 state를 새 run 승인/완료로 해석하지 않는다. 발견 시 명시적으로 구형 형식임을 알리고
   새 실행 명세가 필요함을 안내한다. 사용자 기록은 자동 수정/삭제하지 않는다.
3. 기존 코드의 유용한 저장·redaction·검증 기법은 재사용 가능하다. 공존 제거를 모든 기존 코드의
   일괄 삭제로 해석하지 않는다. 제거 파일 목록은 상세 설계에서 dependency closure와 함께 확정한다.
4. 과거 docs/sdd 문서·승인·실험 증거는 읽기 가능한 역사 기록으로 보존한다.
   과거 산출물 보존은 구형 workflow를 계속 실행 가능하게 유지한다는 뜻이 아니다.
5. 작업 세션이 유지되는 동안 AI는 구현·원인 분석·재계획 판단을 담당하고 script는 확정 DAG의
   실행·결과 수신·검증·정해진 복구를 담당한다. 세션 종료 후 무인 진행을 보장하지 않는다.
6. 예기치 않은 종료에 대비한 durable 상태/증거와 새 세션 재개는 필수다.
   종료 시 worker/test가 이미 살아 있을 수 있으므로 재개 전에 확인하고 중복 실행을 막는다.
   원격 프로세스가 세션 종료와 동시에 모두 멈춘다고 가정하지 않는다.

## 계획·수용 조건 영향

- p1 I6의 legacy coexistence를 새 workflow 단일 진입점·구형 실행 경로 제거·설치 검증으로 바꾼다.
- A21-r2: 설치된 plugin이 새 workflow로 진입하며 구형 phase loop로 분기하지 않는다.
  opaque installed path에서 실행 가능하고 runtime inventory가 실제 closure와 일치한다.
  기존 문서/증거/구형 state는 보존하며, 구형 state를 새 승인이나 완료로 오인하지 않는다.
- A07/A13의 crash/replay/resume 조건은 유지한다. 세션 종료 후 무인 진행 시험은 요구하지 않는다.
- A01–A20의 의도·검증 기준은 유지한다. 기존 workflow 모양만 검사하는 테스트는 변경된 기준에 맞게
  교체하고, 사용자 행동·저장·보안 등 여전히 유효한 회귀 검사는 유지한다. 느리다는 이유로 생략하지 않는다.
- 영향 node는 I6 및 I2/I4의 session lifecycle 경계다. 아직 구현 완료 증거가 없으므로
  무효화할 제품 완료 판정은 없다. E1에서 관찰한 사실은 그대로 유효하다.

## 이번 수정의 경계

설계·계획·Compound 기록만 갱신했다. 구형 skill/core 파일 삭제·manifest 변경·제품 구현은 아직 하지 않았다.
새 공개 명칭과 정확한 제거/재사용 파일 목록은 상세 구현 설계에서 정리한다.

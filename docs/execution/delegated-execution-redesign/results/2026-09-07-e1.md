상태: **현재 인증된 부모 세션이 살아 있는 경로 PASS; detached 지원은 미검증**.
이 결과는 Moondex 제품 전체 구현/수용 테스트 통과가 아니다.

## 승인과 범위

d1 추천 방향 승인과 `approvals/e1-limits.json`에 기록된 사용자 답변을 적용했다.
현재 worktree, Codex 기본 설정, worker 1개, 자동 재시도 0회, 10분 상한.
사용량에 여유가 있다는 답변을 무제한 실행 승인으로 해석하지 않았다.
원래 인수인계 세션에는 worker_done을 보내지 않았고 E1 worker만 자기 Dispatch로 보고했다.

## 실패와 수정

1. collector가 writer lock을 보유한 동안 별도 진단 client 호출이 flock에서 거부됐다.
   외부 RPC 실행 전 거부됐으며 두 번째 writer의 변경은 없었다. collector 종료 후 읽기를 수행했다.
2. 첫 재수신 검사는 응답 envelope 전체를 비교하여 `replayed`와 mutation request ID 변화 때문에 실패했다.
   실제 Delivery ID와 메시지는 동일했다. 비교를 runId/deliveryId/messages/count로 제한했다.
   다른 Run/Delivery/메시지 내용은 계속 거부하는 부정 검사를 추가했고 모두 통과했다.
   worker 재시도 없이 저장된 동일 Delivery로 재검증했다. 기준을 구현 결과에 맞춰 완화한 것이 아니다.

## 검증 범위

로컬 검사는 실제 프로세스 중단 후 SQLite 중복 제거, unknown mutation 재시도 차단,
성공 receipt 재사용/argv 변경 거부, 잘못된 fixture와 stale nonce 거부를 포함했다.
이 로컬 검사를 live Orca의 unknown launch response recovery 증거로 대체하지 않는다.

E1은 staged script 실험이다. 스크립트가 실제 생성/수신/재시작/검증/정리 RPC를 수행했지만,
응답 schema 확인과 비교 오류 수정 사이에 사람이 읽을 수 있는 agent 조사 단계가 있었다.
따라서 제품의 무인 DAG scheduler가 완성되었다고 할 수 없다.

## 미검증과 다음 설계 영향

- 부모 세션이 idle/종료한 뒤 권한 지속, 다른 coordinator terminal에서의 정당한 재개.
- worker-start 응답 손실 후 외부 side effect 중복 방지, 강제 deadline watchdog의 장애 복구.
- 같은 worker의 후속 Task 재사용, 병렬 노드와 공유 자원 lock, 질문/예산 개입.
- 실제 token/금액 측정·상한 강제. 기본 model의 정확한 식별.
- Moondex 전체 A01–A21과 package 설치 검증.

인증된 부모 세션의 child script에서 시작하고, 권한 불명확 시 RECOVERING/WAITING_USER로
보존하는 설계를 구체화할 근거를 얻었다. detached 실행을 지원한다고 표시할 근거는 아직 없다.

# d5 — 승인된 구현 기준

사용자가 플랜 모드의 「Moondex 위임 실행 구조 구현 계획」에 “Implement the plan.”으로 구현을 요청했다.
출처는 이 대화의 직전 proposed_plan과 후속 사용자 메시지다. 별도 메시지 ID나 과거 승인을 발명하지 않는다.
이 문서는 해당 계획을 구현에 연결하는 기준이며 d1–d4와 승인/실험 기록은 보존한다.

## 합의와 범위

- 준비 형식 자유, 목표/설계/범위/검증 조건을 revision bundle로 고정하고 사용자 결정 원문·출처·digest로 승인한다.
- 현재 대화 AI가 기본 구현자다. script가 DAG/동시성/결과 수신/전이/검증/정해진 복구를 소유한다.
- 기본 동시성 1, 시간 이익과 독립성이 있는 작업만 명시된 상한으로 Orca 분할한다.
- AI는 submit 후 advance를 호출한다. script만 상태를 쓴다. status는 읽기 전용이다.
- 파일 저장과 .moondex/STATE.json. 불변 receipt → fsync event → atomic snapshot 순서, intent-before-effect.
- 한 worktree의 활성 run 하나. event가 복구 권위. snapshot은 조회용. 이중 writer/중복 작업/오래된 결과를 거부한다.
- 총시간/토큰 제한 없음. 긴 필수 build/unit/integration/E2E를 생략/분할/실패로 간주하지 않는다.
- 최초 실패 후 자동 복구 최대 2회. 정상 대기/중단 재개/중복 전달은 횟수에 포함하지 않는다.
- 플랫폼 한도·권한·정보 부족·불명확 외부 결과는 상태/증거/영향을 저장하고 개입한다. 세션 밖 무인 scheduler 없음.
- 필수 gate는 script가 실행. actual tree/input/definition/env/argv/exit/log/assertion/count와 의도 검토를 연결한다.
- worker_done/exit 0/과거 PASS만으로 완료 불가. 통합 snapshot에서 필수 검증·의도 검토·결과·필수 기록까지 완료한다.
- 기준 변경은 새 사용자 합의와 baseline revision. 같은 기준/scope의 plan 변경은 기록 후 자동 허용.
- 구현 결함과 검증 결함은 별도 처리. 기대값 완화/N/A 전환은 기준 변경. 영향 증거만 무효화한다.
- Compound는 opt-in이며 이번 작업은 지정 DB 기록 필수. raw 읽기 전용, template/index/hub/log, 동시 편집·재시도 보존.
- 본체는 증거 수집만 하며 자동 self-improve/정책 변경 없음.
- 새 execute 경로로 구형 SDD 실행을 차단. 다른 skill 공통 launcher는 유지하고 광범위 개선은 후속이다.
- 원래 worktree는 읽거나 복사/변경하지 않음. merge/push/deploy/reinstall은 제외.

## 작업 DAG와 통과 조건

I1 → I2 → I3 → I4 → I5 → I6. 각 입력은 선행 코드/계약, 수정은 해당 execution 모듈·검증 및 필수 연결에 한정한다.

| 노드 | 산출물 | 필수 증거 |
|---|---|---|
| I1 | bundle/approval/DAG/scope 계약 | A01–A03,A05: 잘못된 승인, 변조, cycle, 누락 검증 거부 |
| I2 | event/snapshot/상태/current AI 배정 | A04,A07,A13: crash, 이중 advance, stale/duplicate, resume |
| I3 | process/gate/integration | A08–A11: FAIL/zero/stale/tamper/통합 결함 차단, 장기 실행 유지 |
| I4 | Orca adapter/동시성/개입 | A06,A07,A12,A13,A20: 실제 실행, Delivery replay, unknown side effect, cleanup |
| I5 | feedback/invalidation/report/Compound | A14–A19: 영향만 재실행, raw 불변, 사용자 편집 보존, 중단 재개 |
| I6 | skill/설치/SDD 퇴역/CI | A21-r2와 전체: package-relative 실제 실행, 과거 기록 보존 |

추가 필수: production current-session E2E, 실제 Orca A/B 및 A→C 동시성2 시험, 복구2회와 소진/답변/재개,
사용자 행동 browser E2E, 전체 pytest 및 AGENTS 정적 검사. simulation은 live Orca를 대체하지 않는다.
기존 8개 실패 복구는 선행 조건이 아니나 유지 기능의 최종 실패는 해결한다. retired 형식 시험은 기준 대응표와 함께 교체한다.

## 공개 행동

execute prepare/approve/status/advance/submit/resume/feedback/answer/cancel/report.
advance 반환은 ACTION, WAITING_PROCESS, WAITING_USER, RECOVERY_REQUIRED, COMPLETED.
Node: PENDING→READY→RUNNING→SUBMITTED→VERIFYING→SUCCEEDED. failed/unknown/invalidated 보존.
30초 관찰 창은 종료 deadline이 아니다. AI에게 반환된 작업은 먼저 저장되어 반복 호출로 중복 배정되지 않는다.

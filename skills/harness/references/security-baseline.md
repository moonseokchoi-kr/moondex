# 보안 점검 참고

요청된 환경과 변경 범위에 관련된 항목을 선택한다. Hook 등록 지침이 아니며,
검사 이름이나 파일 존재만으로 보호된다고 판단하지 않는다.

- 시크릿이 코드·로그·보고서에 노출되는지 확인한다. 원본 재현 자료와 redacted 출력의 위치를 구분한다.
- 입력 검증, 인증/인가, SQL parameter binding은 실제 경로와 실패 사례로 확인한다.
- `.env`와 키 파일의 추적 여부를 확인하되, 승인 없이 사용자 파일을 삭제하거나 자격증명을 변경하지 않는다.
- 파일 경계와 symlink escape, report가 원본 evidence를 덮어쓰는 경우를 검증한다.
- 파괴적 작업은 요청 범위와 실제 대상을 확인한다. 토큰 패턴 하나로 명령의 안전성을 단정하지 않는다.
- 설정을 수정할 때 기존 항목을 보존하고, 명시적으로 요청하지 않은 자동 hook을 추가하지 않는다.

결과에는 실행한 검사, 관찰된 문제, 미검증 범위와 필요한 조치를 적는다.

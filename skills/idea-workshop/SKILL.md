# Idea Workshop

사용자가 원하는 준비 결과를 만든다. 아이디어 발산, 방향 비교, 조사, PRD는 선택 가능한 작업이며
필수 단계 순서가 아니다. 이미 합의한 요구를 다시 워크숍으로 돌리지 않는다.

## 필요한 작업 선택

- 막연한 아이디어: 구체적인 경험과 불편에서 문제·대상·원하는 행동을 찾는다.
- 방향 비교: 문제/대상/해결 방식 중 고정된 것과 바꿀 수 있는 것을 나누고,
  역발상·대상 전환·인접 사례·범위 축소 등 관련 있는 관점으로 대안을 비교한다.
- 검증: 중요한 가정부터 실제 근거를 찾는다. 출처·관찰·추정·미확인을 구분하고
  반례와 실패 조건도 기록한다. 사용자 제공 자료나 사용 가능한 조사 도구를 이용한다.
  도구 부재를 사실 확인으로 대신하지 않는다.
- PRD: 사용자가 요청한 깊이로 문제, 사용자 행동, 범위/제외, 주요 설계 선택,
  통과/실패 조건과 미결정 사항을 정리한다. 기존 문서가 있으면 그 구조를 존중한다.

기본은 현재 세션에서 수행한다. 조사 주제가 여러 개라는 이유만으로 팀을 만들지 않는다.
승인된 위임이 실제 시간 이익을 주는 경우에만 목표·입력·수정 범위·의존성·검증·증거를
명시해 `$moondex:execute`로 실행한다. 작업 선택·재시도는 스크립트 소유다.
조사 부족은 누락된 근거로 보고하고, 문서 수나 인용 개수만으로 품질을 판정하지 않는다.

## 기록과 구현 연결

사용자가 지정한 문서 위치와 지식 DB 규칙을 따른다. 프로젝트 PRD를 요청했고 별도 위치가
없다면 `docs/PRD.md`, 필요하면 `docs/research/`에 출처를 보존할 수 있다.
PRD 작성 자체는 구현 승인이나 실행 성공 증거가 아니다.
구현 요청이 있으면 합의된 내용과 실제 승인 출처를 `$moondex:execute`에 연결한다.
기준 변경에는 새 합의와 revision이 필요하다. 문서 형식을 이유로 기존 승인을 반복 요구하지 않는다.
